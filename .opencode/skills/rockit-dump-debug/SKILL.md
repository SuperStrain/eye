# Rockit DUMP 调试

## 概述

DUMP 是证据，不是根因。先定位链路阶段，再选择能够区分候选原因的最小 DUMP；单个计数器、超时或命令错误都不能单独定根因。

## 使用范围

仅用于 RV1126B 的 Rockchip Rockit MPI 多媒体问题；Rockit 通用问题可涉及 VI、VPSS、VENC、GetStream、码流、帧率和 buffer，但当前 eye 的 RV1126B 实现是 VI -> VENC，不使用 VPSS。不要把 Hi3516CV610、纯构建问题或非 Rockit 实现套入本流程，也不要假设当前 eye 存在 VPSS 路径。

## 必需子技能

问题诊断必须通过技能名要求 `systematic-debugging`。只有完成设备访问两轮握手且确实进入连接阶段时，才要求通过技能名使用 `embedded-device-debug`，并遵守其配置读取和确认流程。

## 诊断流程

1. 先确认平台是 RV1126B/Rockit，再记录现象、发生时间、模块、通道和已有原始输出。
2. 读取项目映射，按实际拓扑定位阶段：VI 输入、SYS 绑定、VENC 编码、GetStream/ReleaseStream 或下游 RTSP；不要用 VPSS 替代不存在的节点。
3. 根据症状选择最小只读 DUMP：初始化失败看首个 MPI 错误；所有流无数据结合 `sys`、`vi`、`venc`；单路沿对应 VI/VENC 通道；内存问题看 `mb`/`mb d`；RTSP 问题继续看分发器和网络。凡响应建议任何 `dumpsys` 命令，必须在命令前固定列出并逐项核对两个前提：`1. 目标应用已成功调用 RK_MPI_SYS_Init`；`2. 目标应用进程仍存活`。未核对两项前不得给出该命令。
4. 把输出分为事实、异常、推断和待验证项。`in_fps=30/out_fps=0` 只能说明 VENC 阶段存在异常线索；`dumpsys sys not found` 进入命令可用性异常分支，必须同时核对工具路径/版本、eye 应用进程是否存活以及应用是否已完成 `RK_MPI_SYS_Init`，再区分路径/SDK 差异和模块不可用。日志只按相关关键词和时间范围读取，不默认 `cat` 全量日志。
5. 为每个候选原因给出下一项验证、预期结果和风险，不凭单点证据给出唯一根因。

## 参考加载

涉及命令或字段时先读 `references/dump-debug.md`，只使用其中已验证的命令和字段，并记住应用须已调用 `RK_MPI_SYS_Init` 且进程仍在运行。涉及 eye 的通道、参数、日志或输出路径时读 `references/eye-rv1126b.md`。

## 设备访问门

任何实际连接尝试，无论是用户请求还是代理主动判断有必要，无论现在连接还是稍后连接，都必须先输出并逐行填写以下固定五行表，五行不能合并成列表或省略：

| 项目 | 当前用户消息已确认 | 仍缺失，请提供 |
|---|---|---|
| 协议 |  |  |
| 地址（主机/IP+端口） |  |  |
| 账号/凭据方式 |  |  |
| 已获授权 |  |  |
| 允许的命令范围 |  |  |

第一轮握手只能输出上述五行表并逐项请求缺口；初始消息中的“立即连接”“以前连过”、代理的主动判断或持久配置候选都不构成后续确认，也不能触发 `embedded-device-debug`、Telnet、SSH、串口或任何网络连接工具。只有用户在后续一轮明确确认解析后的五项全部内容（主机/IP+端口、账号、凭据方式、连接授权、允许的命令范围）后，才进入第二轮完整确认；第二轮完成前仍不得连接，此后才可调用 `embedded-device-debug` 或连接工具。持久配置只能填入候选列，对应确认槽仍保持未确认，禁止用于实际连接。只有当前会话中可引用的用户原话才可列入“当前用户消息已确认”；若声称协议或参数冲突，必须引用当前会话中的两条实际冲突信息，否则不得声称冲突。Telnet/SSH 的地址槽必须同时包含主机/IP 和端口；五行中任一项未补齐前，只能把远程步骤标为授权后的候选，不能给出看似可立即执行的远程步骤。初始阶段只读；不执行写文件、采集落盘、杀进程、重启、改配置或改变调试状态。任何行为变更都要单独取得明确批准，重启不能从“可以处理”推定获得授权。对任何写设备文件的操作，除单独取得明确批准外，还必须先核对目标路径、预估输出大小和可用空间，并说明覆盖风险；完成这些披露后，必须再次请求明确执行批准，笼统的“立即 dump”不替代该确认。空间检查命令按 `embedded-device-debug` 流程选择，不从 PDF 命令参考臆造。

## 输出合同

当证据只有单次或单来源 DUMP 时，输出固定为以下五段顺序，不能输出独立候选原因、最可能原因或置信度因果结论：问题分类（中性）；原始证据逐字；字段四列表；最小下一步命令及预期；风险。凡分析 DUMP 字段或计数器，必须逐行填写以下固定表；候选方向只能写在“优先怀疑阶段”列，同一字段不得在表外改写：

| 现象/字段 | 异常线索 | 优先怀疑阶段 | 下一项区分性证据 |
|---|---|---|---|
|  |  |  |  |

每个字段至少占一行，并填写“异常线索”“优先怀疑阶段”和“下一项区分性证据”；只有独立证据交叉验证后，才可在事实/结论段落表达确定因果。

字段表后固定写：`现有证据仅支持上述优先检查顺序，不支持确定因果。` 只有至少两项相互独立的证据完成交叉验证后，才可增加候选原因、最可能原因和置信度；每一项都必须逐项引用支撑证据，并保留未证实的替代解释。多证据输出仍须保留原始证据和对应区分性证据。

## 快速映射

- 初始化失败：首个 `RK_MPI_*` 错误及 VI、VENC、Bind 阶段。
- 所有流无数据：`sys`、`vi`、`venc` 与 eye 日志的共同证据。
- 单路异常：对应 VI 通道、VENC 通道和 `STREAM`/`TEST` 输出。
- GetStream 超时：VENC 输入/输出推进、取流计数和 `STREAM` 日志；不要伪造错误码。
- 内存增长或卡死：`mb` 与 `mb d` 的 block、长度、refs、归属随时间的变化。
- 下游 RTSP 无流：区分取流/文件、分发器、RTSP 注册和网络；文件增长不等于全链路正常。

## 常见错误

不要猜节点或设备参数，不要把默认 VPSS 拓扑套到 eye RV1126B，不要一开始使用全量 dump，不要忽略 `RK_MPI_SYS_Init` 和进程存活前提，不要用单点证据定根因，不要把 `dumpsys` 命令未找到误写成子命令不存在，也不要未经批准写文件、采集、杀进程或重启。

### 红旗自检

发送前扫描草稿中的确定因果短语：`根因在`、`证明`、`可以确认`、`未推进`、`没有输出`、`输出没有推进`。若判断只来自单一 DUMP 字段或计数器，红旗出现即停止发送，将该行改成“未观察到推进的线索 / 优先检查阶段 / 需用 X 交叉验证”，并把 X 填入固定 DUMP 字段表的“下一项区分性证据”列。
